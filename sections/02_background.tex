\section{Background and Related Work}
\label{sec:background}

\subsection{Macroscopic and Diagnostic Code Benchmarks}

Broad code benchmarks measure realistic programming capabilities, including function synthesis, issue resolution, defect repair, and code understanding. Examples include HumanEval, APPS, CodeXGLUE, Defects4J, SWE-bench, LiveCodeBench, and BigCodeBench~\cite{chen2021codex,hendrycks2021apps,lu2021codexglue,just2014defects4j,jimenez2024swebench,jain2024livecodebench,zhuo2024bigcodebench}. Such benchmarks are valuable because they capture end-to-end behavior on tasks closer to developer workflows. Their breadth also makes them less diagnostic when the goal is to isolate one elementary structural capability.

Controlled diagnostic benchmarks make the opposite trade-off. They reduce ecological realism to gain control over input generation, difficulty factors, and oracle computation. \benchmark follows this diagnostic philosophy: generated Java programs are synthetic, but their structure is known exactly, and every reachability label and trace can be checked programmatically.

\subsection{Program-Analysis Background}

In a call graph, nodes represent methods and directed edges represent possible method calls. A reachability query asks whether a target node can be reached from a source node by following directed call edges. Program-analysis literature has studied call-graph construction and reachability for decades~\cite{grove2001framework,tip2000scalable}. \benchmark does not compete with deterministic program analysis: a graph traversal over the generated oracle graph solves the benchmark by construction. Instead, the benchmark asks whether LLMs can recover and explain this structure from generated Java source code.

\subsection{Trace Explanations}

The benchmark requires models to emit a trace in addition to a final answer. The trace is not used as evidence of hidden internal reasoning. It is an observable output artifact that can be compared with a canonical oracle trace. This distinction matters because a correct final answer can still be accompanied by an invalid transition, a missing intermediate method, or a shortcut that does not match the benchmark's execution-oriented trace convention.
