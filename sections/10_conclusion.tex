\section{Conclusion}
\label{sec:conclusion}

In this paper, we present \benchmark, a generated Java dataset that allows us to study whether a target method executes from a source under concrete values. A separate configurable construction algorithm varies class size, guarded calls, and values passed between methods, so model behavior can be compared across structural difficulties. The labels and executable graphs are validated by running the complete dataset. Evaluating the Boolean answer and method trace separately then allows us to check whether the returned exploration follows calls that can execute.

The results show that a correct answer can come with an incomplete trace or with calls that cannot execute. The trace therefore provides additional information about the program behavior supporting the answer, particularly when questions involve guarded calls, passed values, or complete exploration for negative targets. The CO and EE comparison also shows that models can behave differently on the same dataset when the execution context is made explicit. The gains are modest for Gemma and Qwen3.6, while Qwen3.8-Flash-Next, which we expected to be more capable than these two models, obtains a larger gain in trace correctness on the difficult subset but also produces more non-responses.

This allows us to identify difficulties that would not be visible from final-answer correctness alone. Further evaluation with more models and real programs would help determine how broadly these difficulties transfer.
