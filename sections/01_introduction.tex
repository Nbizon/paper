\section{Introduction}

\begin{itemize}[leftmargin=*]
    \item Open the paper by noting that LLMs are increasingly used for code understanding, explanation, review, and transformation tasks.
    \item State the central problem:
    \begin{itemize}[leftmargin=*]
        \item many evaluations measure the correct final answer on macroscopic tasks;
        \item they say less about how well models perform on simpler tasks.
    \end{itemize}
    \item Explain why this makes evaluation harder:
    \begin{itemize}[leftmargin=*]
        \item macroscopic tasks such as bug fixing combine several microscopic tasks, such as identifier lookup or reachability;
        \item they make it difficult to isolate a precise structural capability.
    \end{itemize}
    \item Introduce the paper's methodological response:
    \begin{itemize}[leftmargin=*]
        \item use controlled reachability tasks;
        \item keep the formulation simple;
        \item impose an exact oracle and explicit difficulty factors.
    \end{itemize}
    \item Justify the choice of reachability:
    \begin{itemize}[leftmargin=*]
        \item it is simple to define;
        \item it supports clean synthetic generation;
        \item it can be verified automatically;
        \item it provides a minimal but useful diagnostic task for structural reasoning.
    \end{itemize}
    \item Introduce the two task families targeted by the final benchmark:
    \begin{itemize}[leftmargin=*]
        \item \textbf{control-flow reachability}: follow call relations between methods;
        \item \textbf{data-flow reachability}: follow the same call relation when method calls can be guarded by conditions that depend on generated variables.
    \end{itemize}
    \item Clarify the scientific progression:
    \begin{itemize}[leftmargin=*]
        \item control flow is the methodologically simpler case;
        \item data flow keeps the same reachability question but requires evaluating the conditions that decide whether guarded calls execute.
    \end{itemize}
    \item Position the experimental program:
    \begin{itemize}[leftmargin=*]
        \item the paper aims for a full comparison between models on both families;
        \item it measures performance and then analyzes the effect of dataset-intrinsic parameters.
    \end{itemize}
\end{itemize}

The target final study is organized around four research questions:
\begin{itemize}[leftmargin=*]
    \item \textbf{RQ1}: how well do LLMs perform on controlled reasoning tasks about reachability between methods?
    \item \textbf{RQ2}: how do structural difficulty factors affect that performance?
    \item \textbf{RQ3}: how does performance differ between control-flow and data-flow reachability tasks?
    \item \textbf{RQ4}: what differences appear between reasoning and non-reasoning models on these tasks, and how does the requested reasoning budget affect reasoning models?
\end{itemize}

\textbf{Contributions.} The paper makes the following contributions:
\begin{itemize}[leftmargin=*]
    \item A controlled Java reachability benchmark for evaluating structural reasoning in LLMs.
    \item Two complementary task families, control-flow and data-flow, sharing a common reachability formulation and a common trace output.
    \item An evaluation protocol that separates final-answer accuracy, trace validity, path fidelity, and behavior across structural factors.
    \item A complete experimental protocol to compare models, measure their performance, and analyze the effect of dataset-intrinsic parameters.
\end{itemize}
