\subsection{\researchq{2}: Models and Inference Configurations}

For \researchq{2}, the comparison unit is the complete configuration listed in Table~\ref{tab:models}. We first compare all configurations under their frozen inference settings. This shows which deployed systems obtain the highest answer and trace scores without assuming that a checkpoint behaves identically under every serving mode.

We then study reasoning budget only for configurations where this value is verified. Requested budgets range from 512 to 16,384 tokens. For each configuration, we identify the smallest budget that reaches at least 95\% of its highest observed final-answer accuracy. We compare this point with the evolution of trace quality and \texttt{NO\_RESPONSE}. This makes it possible to determine whether a larger budget improves only the final decision or also the execution trace. No budget conclusion is reported for a deployment whose control is not confirmed.

\subsection{\researchq{3}: Trace-Level Reasoning and Error Patterns}

\researchq{3} starts from the cases that cannot be explained by the final answer alone. For each response, we compare the Boolean decision with the methods reported in the trace. We first check that the trace starts from the requested source. We then verify every transition and determine whether the model stops at the correct point. This separates a correct answer supported by an executable trace from a correct answer associated with missing or impossible calls.

For condition-aware questions, we additionally check whether an invalid transition corresponds to a call that is visible in the code but disabled at runtime. The error analysis in Section~\ref{sec:error-analysis} uses these checks to group recurring behaviors. Because the two task families are not paired instance by instance, their aggregate differences are estimated with unpaired intervals over similar factor distributions.
