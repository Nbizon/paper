Software-engineering benchmarks evaluate both development outcomes and specific program-understanding capabilities. We propose \benchmark, a generated dataset of Java classes and executable method-reachability questions for examining how controlled factors relate to decisions and supporting evidence. A separate configurable algorithm produces the classes, questions, Boolean labels, and executable-graph oracles; the labels and graphs are independently validated by executing the complete final dataset. The evaluator scores the decision and exploration trace separately, accepting different orders supported by executable calls. On 46,656 questions with the Class-only variant (CO), Qwen~3.6 obtains 87.98\% answer correctness and 67.43\% trace correctness; Gemma~4 obtains 84.21\% and 55.90\%. The strongest difficulties involve guarded calls, passed values, and exhaustive exploration for negative questions. Trace diagnostics locate unsupported calls, omissions, and errors associated with longer value dependencies. The Explicit execution variant (EE) presents the same dataset with the entry point and determinism made explicit, allowing performance and token consumption to be compared. These results illustrate how executable-graph oracles can locate difficulties hidden by final-answer correctness.
