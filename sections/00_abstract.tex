Current software-engineering benchmarks mainly evaluate LLMs on complex tasks that involve several skills at the same time. This makes it difficult to identify the reasons behind a model's success or failure. We propose \benchmark, a benchmark that generates Java programs from automatically generated call graphs and provides questions centered on method reachability. These questions are not limited to the control flow visible in the source code. They can also require the model to reason about data flow and actual runtime behavior. \benchmark is configurable and allows us to control several complexity factors, such as trace length, class size, query polarity, and the number of guarded calls. Because the call graphs are known in advance, the benchmark can rely on an oracle that provides both the expected answer and the correct reasoning trace. We can therefore analyze whether a model reaches the correct answer by following a valid path through the program.
