Current software-engineering benchmarks mainly evaluate LLMs on complex tasks that involve several skills at the same time. This makes it difficult to identify the reasons behind a model's success or failure. We propose \benchmark, a benchmark that generates Java programs from automatically generated call graphs and provides questions centered on method reachability. These questions are not limited to the control flow visible in the source code. They can also require the model to reason about data flow and actual runtime behavior. \benchmark is configurable and allows us to control several complexity factors, such as path length, class size, query polarity, and the number of generated conditions. Because executable call edges are known at generation time, the benchmark provides both the expected Boolean answer and an executable-graph oracle. We can therefore score final-answer correctness and path correctness independently without imposing one canonical traversal.
