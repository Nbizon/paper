Large language models are increasingly evaluated on realistic software-engineering tasks, but end-to-end benchmarks often conflate several capabilities and make it difficult to identify which code properties cause failures. We introduce \benchmark, a Java benchmark for diagnosing executable inter-method reachability under controlled variation. It generates single-class programs with oracle labels and execution-oriented traces, varying canonical distance, class size, query polarity, and condition-aware guards. The benchmark covers unguarded reachability, where visible generated calls execute, and condition-aware reachability, where syntactically visible calls may be disabled by generated conditions. Evaluation separates final-answer correctness from exact trace accuracy, trace completeness, graph-valid exploration, syntactic-call bias, and invalid-output behavior.
