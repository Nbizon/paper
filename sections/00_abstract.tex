Benchmarks have examined static function reachability and runtime call-structure recovery. We propose \benchmark, the final dataset of 1,232 generated Java classes and 46,656 executable method-reachability questions. A separate configurable construction algorithm varies class size, guarded calls, and values passed between methods. This allows us to compare model behavior across controlled levels of structural difficulty. The labels and executable graphs are checked by running the complete dataset. The evaluator scores the Boolean answer and trace separately. The trace lists the methods explored by the model and is checked against executable calls. A positive trace must reach the target. A negative trace must cover all methods reachable from the source. Different valid exploration orders are accepted. On the full Class-only variant (CO), Qwen~3.6 obtains 87.98\% answer correctness and 67.43\% trace correctness, while Gemma~4 obtains 84.21\% and 55.90\%. The results show that answer correctness does not always come with a valid trace. The main difficulties involve guarded calls, passed values, and complete exploration for negative questions. The Explicit execution variant (EE) uses the same dataset but makes the entry point and deterministic execution explicit. Results on the two prompt variants show modest gains for Gemma and Qwen~3.6, and larger trace gains for Qwen3.8-Flash-Next on a difficult subset, together with more non-responses.
