Software-engineering benchmarks evaluate both development outcomes and specific program-understanding capabilities. We propose \benchmark, a generated dataset of Java classes and executable method-reachability questions that allows us to examine how controlled factors relate to model decisions and the evidence provided for them. A separate configurable algorithm produces the classes, questions, Boolean labels, and executable-graph oracles. The labels and graphs are checked independently by running the complete final dataset. The final answer and exploration trace are evaluated separately, accepting different orders supported by executable calls. On 46,656 questions with the Class-only variant (CO), Qwen~3.6 obtains 87.98\% answer correctness and 67.43\% trace correctness, while Gemma~4 obtains 84.21\% and 55.90\%. The main difficulties involve guarded calls, passed values, and exhaustive exploration for negative questions. The traces make it possible to identify unsupported calls, omitted methods, and errors associated with longer value dependencies. The Explicit execution variant (EE) uses the same dataset but makes the entry point and determinism explicit, allowing us to compare performance and token consumption. This evaluation provides information about difficulties that final-answer correctness alone does not reveal.
