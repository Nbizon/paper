Existing benchmarks evaluate code generation, issue resolution, static method reachability, and runtime call-structure recovery. We propose \benchmark, a dataset of 1,232 generated Java classes and 46,656 questions about whether a target method executes from a source under values supplied by a generated execution. A separate configurable algorithm constructs the dataset and varies class size, guarded calls, and values passed between methods. Running the complete dataset validates its labels and executable graphs. Models return a Boolean answer and a method trace. We score these separately by checking answers against labels and traces against executable calls. A positive trace must reach the target, while a negative trace must cover all methods reachable from the source. On the full Class-only (CO) dataset, Qwen~3.6 achieves 87.98\% answer correctness and 67.43\% trace correctness. Gemma~4 achieves 84.21\% and 55.90\%. These results show that correct answers may lack valid traces. Errors concentrate around guarded calls, passed values, and complete exploration for negative questions. The Explicit execution (EE) variant uses the same dataset but makes the entry point and deterministic execution explicit. In the full Qwen~3.6 comparison, EE has slightly higher answer and trace correctness but uses a larger reasoning budget. On a difficult subset of 216 questions evaluated at the same budget, Qwen3.8-Flash-Next's trace correctness rises from 35.65\% to 46.76\% under EE, while non-responses increase from 10.65\% to 19.44\%.
