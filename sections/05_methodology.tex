\subsection{Budget Settings}

The main comparison uses a best-effort budget setting with a comparable total generation allowance across model families. Reasoning models receive a requested reasoning budget of 16,384 tokens and a final-answer budget of 2,048 tokens. Non-reasoning models receive a total generation budget of 18,432 tokens. This setup gives each model a generous opportunity to solve the task while keeping the total generation allowance comparable. We do not claim that this makes reasoning and non-reasoning models identical in computational cost or internal allocation.

\subsection{Prompting Protocol}

The final prompt was calibrated using preliminary experiments to make sure models understood the task, produced valid JSON, and were not instructed to use a named traversal algorithm. The prompt defines the trace as an explored call sequence, not as the shortest path. It tells the model to follow method calls in the order they appear in the code, start from the caller, and continue until the target is reached or no further reachable calls remain.

For control-flow instances, the prompt does not mention condition evaluation. For condition-aware instances, the prompt states that the model must account for conditions and variable values that determine whether guarded calls are executed. The prompt includes a small illustrative example where the expected trace is \texttt{["A", "B", "C", "D", "E"]}; this clarifies that traces should list the explored call sequence in code order, rather than only a shorter source-target chain.

\subsection{Oracle Validation Reminder}

Before evaluation, the oracle-validation pipeline checks compilation, materialized call consistency, positive and negative reachability labels, canonical traces, and condition evaluation for guarded calls. We use programmatic analysis tools for oracle validation and dataset sanity checks, not as competing baselines. A deterministic program-analysis algorithm can solve the generated reachability task by construction; the scientific question is whether LLMs can recover and explain this structure from generated Java code.
