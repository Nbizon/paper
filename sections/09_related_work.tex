\section{Related Work}
\label{sec:related-work}

\subsection{Task Completion and Program Understanding}

HumanEval, MBPP, and APPS evaluate generated code by checking whether it passes tests~\cite{chen2021codex,austin2021program,hendrycks2021apps}. CodeXGLUE extends evaluation to both understanding and generation~\cite{lu2021codexglue}. LiveCodeBench also includes execution and test-output prediction~\cite{jain2025livecodebench}, while BigCodeBench emphasizes the composition of library calls~\cite{zhuo2025bigcodebench}. At the repository level, SWE-bench evaluates issue resolution~\cite{jimenez2024swebench}. Defects4J provides real Java defects together with tests for repair studies~\cite{just2014defects4j}. \benchmark focuses on executable relationships between methods and on the evidence returned for each reachability decision.

\subsection{Runtime Behavior and Dependencies}

Other benchmarks examine more specific properties of program behavior. CRUXEval predicts inputs or outputs for short Python functions, and REval evaluates predictions about runtime behavior and intermediate states~\cite{gu2024cruxeval,chen2025reval}. Xie et al.'s CoRE evaluates static data and control dependencies and information flow, while Gao et al.'s CoRE tests implementation invariance and predictions about intermediate execution states~\cite{xie2025core,gao2026core}. SemBench includes function reachability, defined by connectivity in a static call graph over real-world C programs~\cite{xu2026semb}. TraceEval instead asks models to recover runtime call structures from repository-derived programs, with edges verified through execution~\cite{li2026traceeval}. CABRA also uses generated call-graph transformations to control task difficulty, but evaluates code-editing tasks with coding agents~\cite{balepur2026cabra}. \benchmark asks whether a target method executes from a source under values supplied by one generated execution. This differs from static function reachability and full runtime call-structure recovery. Its configurable parameters vary class size, guarded execution, and values passed between methods. This allows us to compare model behavior across controlled structural difficulties. The evaluator scores the Boolean answer and method trace separately. Checking the trace against the executable graph shows whether the explored methods follow calls that can execute. The benchmark covers a narrower range of Java behavior than repository-derived corpora.

\subsection{Reachability and Call-Graph Analysis}

Call-graph analysis studies the relationships needed to determine possible calls~\cite{grove2001framework,tip2000scalable}. In our tasks, reachability concerns the calls that can execute under a fixed invocation context. \benchmark uses this graph representation to check the relationships identified by the model, including visible calls disabled by conditions and methods omitted from the source-reachable region.
