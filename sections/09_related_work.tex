\section{Related Work}
\label{sec:related-work}

\subsection{Task Completion and Program Understanding}

HumanEval, MBPP, and APPS evaluate generated code by checking whether it passes tests~\cite{chen2021codex,austin2021program,hendrycks2021apps}. CodeXGLUE extends evaluation to both understanding and generation~\cite{lu2021codexglue}. LiveCodeBench also includes execution and test-output prediction~\cite{jain2025livecodebench}, while BigCodeBench emphasizes the composition of library calls~\cite{zhuo2025bigcodebench}. At the repository level, SWE-bench evaluates issue resolution~\cite{jimenez2024swebench}. Defects4J provides real Java defects together with tests for repair studies~\cite{just2014defects4j}. \benchmark focuses on executable relationships between methods and on the evidence returned for each reachability decision.

\subsection{Runtime Behavior and Dependencies}

Other benchmarks examine more specific properties of program behavior. CRUXEval asks models to predict inputs or outputs for short Python functions~\cite{gu2024cruxeval}. REval examines intermediate runtime behavior and consistency between predictions~\cite{chen2025reval}. CoRE studies dependencies and information flow using static-analysis tasks verified by humans~\cite{xie2025core}, while TraceEval recovers runtime call structure from repository-derived programs using edges verified by execution~\cite{li2026traceeval}. RE2-Bench relates code reasoning to program complexity~\cite{liu2025re2bench}. These works already make it possible to evaluate semantic properties and diagnose difficulties. \benchmark combines controlled generation of call structure and value propagation with an oracle validated by execution on the final dataset. The final answer and exploration trace are evaluated separately. Factors such as \path{n_if}, \path{n_params}, \path{class_size}, and code presentation are varied in the generated grid, while the oracle accepts different valid exploration orders. This makes it possible to compare error patterns across the configured factors. The resulting evaluation complements broader program corpora, while covering a narrower range of Java behavior.

\subsection{Reachability and Call-Graph Analysis}

Call-graph analysis studies the relationships needed to determine possible calls~\cite{grove2001framework,tip2000scalable}. In our tasks, reachability concerns the calls that can execute under a fixed invocation context. \benchmark uses this graph representation to check the relationships identified by the model, including visible calls disabled by conditions and methods omitted from the source-reachable region.
