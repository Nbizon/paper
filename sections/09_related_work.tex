\section{Related Work}
\label{sec:related-work}

\subsection{Task Completion and Program Understanding}

HumanEval, MBPP, and APPS evaluate generated code through tests~\cite{chen2021codex,austin2021program,hendrycks2021apps}. CodeXGLUE covers understanding and generation~\cite{lu2021codexglue}; LiveCodeBench includes execution and test-output prediction~\cite{jain2025livecodebench}; and BigCodeBench emphasizes library-call composition~\cite{zhuo2025bigcodebench}. SWE-bench evaluates repository issue resolution~\cite{jimenez2024swebench}, while Defects4J supplies real Java defects and tests for repair studies~\cite{just2014defects4j}. \benchmark focuses on executable relationships between methods and on the evidence returned for each reachability decision.

\subsection{Runtime Behavior and Dependencies}

CRUXEval evaluates input and output prediction for short Python functions~\cite{gu2024cruxeval}. REval examines intermediate runtime behavior and consistency between predictions~\cite{chen2025reval}. CoRE studies dependencies and information flow through human-verified static-analysis tasks~\cite{xie2025core}. TraceEval recovers runtime call structure with execution-verified edges from repository-derived programs~\cite{li2026traceeval}. RE2-Bench relates code reasoning to program complexity~\cite{liu2025re2bench}. \benchmark contributes a controlled combination of generated call structure and value propagation, an execution-validated oracle for the final dataset, and separate decision and trace scores. The generated grid varies guards, parameters, class size, and presentation factors, while the oracle accepts different executable exploration orders. This combination supports comparisons of error patterns across configured factors. The resulting evidence complements broader program corpora, with a narrower range of Java behavior.

\subsection{Reachability and Call-Graph Analysis}

Call-graph analysis studies the relationships needed to determine possible calls~\cite{grove2001framework,tip2000scalable}. Our task concerns executable reachability under a fixed invocation context. \benchmark uses this graph representation to check the method relationships recovered by a model, including calls disabled by guards and omissions from the source-reachable region.
