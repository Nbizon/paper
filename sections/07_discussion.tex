\section{Error Analysis}
\label{sec:error-analysis}

Aggregate scores indicate how often a model configuration fails, but they do not explain what happened in the generated trace. We therefore complement the main metrics with an error analysis. An interactive dashboard groups failed traces according to structural factors, model configuration, verified reasoning budget when available, and local graph motif. These groups are used to count recurring error types and inspect representative examples.

The taxonomy connects a decrease in a metric with a concrete behavior in the trace. Syntactic-call bias, for example, indicates that the model treated a visible call as executable without evaluating its condition. Missing-node and shortcut errors represent another situation: the final answer can be correct even though required calls are absent from the trace. Invalid transitions, incorrect starting methods, repeated methods, and stopping errors describe other differences between the predicted trace and the oracle.

The dashboard is used to inspect these patterns, but it does not define the main benchmark scores. These scores are computed by the frozen evaluator.
